# Уведомления ученику о домашке — дизайн

Дата: 2026-07-23. Обсуждено со Стасом, решения зафиксированы.

## Проблема

Сейчас ученик узнаёт о назначенном ДЗ только если сам откроет PWA и зайдёт в раздел
«Домашка». Ни push, ни телеграм, ни даже in-app индикатора нет.

## Решения (со Стасом)

- **Каналы:** in-app поп-ап + телеграм (Фаза 1); web push — Фаза 2 (отдельно).
- **События:** новое ДЗ назначено; напоминание о сроке.
- **Поп-ап:** центральный модал при заходе, **раз в день на ученика**, пока есть невыполненное ДЗ; кнопки «Перейти к ДЗ» / «Закрыть».
- Уведомление учителю о сдаче — НЕ в этой работе.

## Охват каналов (прод, 73 ученика)

Телеграм 38 (52%), Яндекс 16, Google 12, без OAuth 7. ~48% недосягаемы в телеге →
их закрывает in-app поп-ап (Фаза 1) и web push (Фаза 2).

## Архитектура

### Предусловие: сохранять срок

`assignFromPicker` сейчас НЕ пишет `deadline` в `homeworks.deadline_at`. Чинится первой
задачей — иначе напоминаниям не на что опираться.

### `StudentNotifier` (сервис)

Один метод: `notify(User $student, string $text, ?string $url)`. Внутри — маршрутизация
по каналам:
- **Телеграм:** если `oauth_provider === 'telegram'` — Guzzle POST на `sendMessage`
  бота (токен `services.telegram.bot_token`, паттерн из `BugReportController`), с
  inline-кнопкой-ссылкой «Открыть» (URL на `student.palomatika.ru/homework`). Ошибка
  доставки (403 — не жал Start, таймаут) → лог + `false`, запрос не роняем.
- **In-app:** поп-ап читает состояние из БД при заходе (отдельного «отправить» нет).
- **Web push:** Фаза 2 (метод-заглушка).

### Событие 1 — новое ДЗ назначено

В `assignHomework` после создания `homework_assignments` → по каждому ученику вызвать
`StudentNotifier`: «📚 Тебе задали домашку: {title}, {N} задач. Срок: {deadline}. [Открыть]».
Идемпотентность: `homework_assignments.notified_at` — не слать повторно.

### Событие 2 — напоминание о сроке

Artisan-команда `homework:remind-deadlines` в планировщике (`app/Console/Kernel.php`,
раз в день утром — рядом с `grades:promote`). Находит назначения `status != completed`,
у чьего `homework.deadline_at` срок сегодня/завтра → шлёт «⏰ Напоминание: {title} до
{deadline}. [Открыть]». Дедуп: `homework_assignments.reminded_at` (не чаще раза в день).

### In-app поп-ап (раз в день на ученика)

В `StudentController::dashboard`: есть ли у ученика назначения `status != completed`.
Если да и `users.homework_popup_shown_on !== сегодня` → в дашборд передаётся флаг +
данные ближайшего по сроку ДЗ; blade рендерит центральный модал (Alpine): заголовок,
«{done}/{total}», кнопки «Перейти к ДЗ» (→ `/homework` или прямо к назначению) и
«Закрыть». Показ фиксируется: при рендере ставим `homework_popup_shown_on = сегодня`
(один показ в день, даже если закрыл).

## Изменения в данных

- `homeworks.deadline_at` — уже в схеме, начать сохранять (Task 1).
- `homework_assignments.notified_at` (datetime, nullable) — дедуп уведомления о новом ДЗ.
- `homework_assignments.reminded_at` (datetime, nullable) — дедуп напоминаний.
- `users.homework_popup_shown_on` (date, nullable) — анти-надоедание поп-апа.

## Крайние случаи

- Ученик без телеграма → только поп-ап (и push в Фазе 2).
- Бот не может писать (403) → лог, `notified_at` не ставим (повторим при след. назначении? нет — ставим, чтобы не долбить; недоставку глотаем).
- Несколько невыполненных ДЗ → поп-ап про ближайшее по сроку (или новейшее, если сроков нет).
- ДЗ без срока → в напоминания не попадает; поп-ап показывает как обычно.
- Пересоздание ДЗ по тому же уроку → новые assignments, новые уведомления (ожидаемо).

## Тесты

- `assignFromPicker` сохраняет `deadline_at`.
- `StudentNotifier`: телеграм-ученик → HTTP-вызов (Http::fake); не-телеграм → без вызова; 403 → не падает.
- Назначение ДЗ → `notified_at` проставлен, повторный вызов не дублирует.
- `homework:remind-deadlines`: выбирает только незавершённые с близким сроком, ставит `reminded_at`, не шлёт дважды.
- Поп-ап: dashboard отдаёт флаг при невыполненном ДЗ и `shown_on != сегодня`; после показа `shown_on = сегодня`; второй заход в тот же день — без поп-апа.

## Фаза 2 (позже)

Web push: VAPID-ключи, таблица подписок, обработчик push в service worker, permission-UX,
iOS-PWA нюанс (только для установленных на домашний экран, iOS 16.4+). `StudentNotifier`
получает третий канал.
