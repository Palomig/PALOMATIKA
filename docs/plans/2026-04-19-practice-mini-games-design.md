# Practice Mini-Games Design

**Goal:** добавить в student PWA новый раздел `Практика` с веткой `Мини-игры` и первой темой `Уравнения`, где ученик проходит бесконечный забег до первой ошибки с таймером 10 секунд на ход.

**User Flow**

- На student dashboard кнопка `Разбор ошибок` заменяется на `Практика`.
- Экран `Практика` показывает вход в `Мини-игры`.
- Экран `Мини-игры` показывает список тем. На старте активна только тема `Уравнения`.
- Экран темы объясняет правила забега: 10 секунд на ход, счётчик правильных ответов, игра завершается на первой ошибке или таймауте.
- Экран игры показывает пример, два ответа, таймер, счёт и текущий уровень сложности.
- После проигрыша показывается экран `Игра окончена` с итоговым счётом, короткой теорией по теме и кнопкой `Сыграть ещё`.

**Architecture**

- Новые маршруты живут в student PWA рядом с текущими `mini` и `full` сценариями.
- Раздел практики управляется отдельным контроллером, чтобы не раздувать `StudentController`.
- Список игр и уровней хранится в конфиге `config/practice_games.php`.
- Генерация задач вынесена в сервис `PracticeGameService`, который:
  - выбирает уровень по текущему счёту;
  - выбирает тип задания из списка доступных для уровня;
  - генерирует конкретный пример и 2 ответа;
  - отдаёт теорию темы для экрана результата.

**Content Model**

- Игра описывается через `slug`, `title`, `description`, `intro`, `theory`, `levels`.
- Каждый уровень задаётся диапазоном счёта и списком `task_types`.
- Каждый `task_type` описывает конкретный дидактический шаблон:
  - перенос положительного слагаемого;
  - перенос отрицательного слагаемого;
  - перенос множителя;
  - перенос отрицательного множителя;
  - перенос слагаемого рядом с коэффициентом.
- Пул задач расширяется не списком жёстко зашитых примеров, а параметрической генерацией по шаблонам и диапазонам чисел.
- Жёсткая межсессионная защита от повторов не требуется; разнообразие обеспечивается за счёт большого количества комбинаций и редактируемых шаблонов.

**Game State**

- Игровой цикл работает на клиенте через Alpine.
- Клиент хранит локально:
  - `score`;
  - `question`;
  - `timeLeft`;
  - `status` (`intro`, `playing`, `result`);
  - `resultReason` (`wrong`, `timeout`);
  - `theory`.
- Каждый следующий вопрос запрашивается у API-эндпоинта с текущим счётом.
- Сервер не хранит прогресс забега в БД на первом этапе.

**Editing Surface**

- Чтобы менять состав уровней, редактируется только `config/practice_games.php`.
- Чтобы расширять пул, добавляются новые `task_types` и диапазоны генерации в `PracticeGameService`.
- Чтобы править объяснение после игры, редактируется блок `theory` в конфиге темы.

**Testing**

- Feature tests:
  - новые страницы `Практика`, `Мини-игры`, `Уравнения` доступны авторизованному ученику;
  - на dashboard есть CTA `Практика`, а `Разбор ошибок` больше не отображается;
  - API вопроса возвращает корректную структуру для темы `Уравнения`.
- Unit tests:
  - выбор уровня по счёту;
  - корректность генерации для ключевых типов заданий;
  - правильный ответ соответствует правилу переноса.

**Non-Goals**

- Нет сохранения рекордов в БД.
- Нет нескольких тем на старте, кроме `Уравнений`.
- Нет сложной анти-повторной системы между забегами.
