# Вторая стадия домашки: «разобрать на уроке»

**Дата:** 2026-08-13
**Статус:** дизайн согласован, реализация не начата

## Задача

У домашки появляется вторая стадия. Проверяя работу ученика, учитель отмечает
часть заданий как «надо разобрать» и приписывает к ним заметки. Отмеченное
становится повесткой ближайшего урока с этим учеником.

Сегодня учитель может написать заметку вида `todo` («разобрать на уроке») в
форме под задачей, но это свободный текст в общей ленте заметок: он не
привязан к задаче ссылкой, не имеет состояния «разобрали / ещё нет» и никуда
не уезжает.

## Что уже есть в системе

- `student_notes` с видами `weakness | strength | todo | general`, полями
  `task_ref` (строка «Задача 2») и `homework_assignment_id`. Форма заметки на
  странице проверки пишет именно сюда.
- Уроки (`lesson_sessions`) со списком задач (`lesson_session_tasks`),
  экраном подготовки (`pwa.teacher.lesson-prep`) и live-режимом.
- Мостик **урок → домашка**: `LessonHomeworkSuggestionService` после урока
  предлагает аналоги задач для нового ДЗ. Мостика в обратную сторону нет.
- Фото решений (`homework_solution_photos`) и маршрут к ним —
  `pwa.teacher.homework.solution-photo`, доступный **только учителю**.

Существенное ограничение: `homework_topic_tasks.task_payload` хранит уже
отрезолвленную задачу, но **не хранит** `bank` + `refs`. Урок принимает задачи
только по `bank` + `refs`, поэтому «перекинуть ровно эту задачу в урок» через
существующий `addTask` невозможно. Дизайн ниже эту проблему обходит, а не
решает: разбор — не задача урока.

## Принятые решения

| Вопрос | Решение |
|---|---|
| Куда ведёт отметка | В подготовку урока с этим учеником |
| Что видно на уроке | Условие + фото решения ученика + заметка учителя. Решать заново не нужно |
| Когда отметка гаснет | Сама, когда урок завершён |
| Как устроено на уроке | Отдельная панель «Разбор», `lesson_session_tasks` не трогаем |
| Видит ли ученик | Да — блок «Разбор» в его экране урока, только чтение, только своя домашка |
| Синхронизация экранов | Нет. Все карточки видны сразу, «текущей карточки» не вводим |

## Модель данных

Новая таблица `homework_review_items`:

```
id
student_id            FK users, cascade
teacher_id            FK users, cascade
homework_assignment_id FK homework_assignments, cascade
homework_topic_task_id FK homework_topic_tasks, cascade
note                  text nullable      — короткая приписка «что именно разобрать»
student_note_id       FK student_notes nullable, nullOnDelete
status                enum: pending | planned | done
lesson_session_id     FK lesson_sessions nullable, nullOnDelete
created_at, resolved_at

unique (homework_assignment_id, homework_topic_task_id)
index  (student_id, status)
index  (lesson_session_id)
```

Статусы: `pending` — отмечено на проверке; `planned` — добавлено в конкретный
урок; `done` — этот урок завершён.

### Почему не флаг на `homework_topic_task_submissions`

Дешевле на одну таблицу, но **несданную задачу отметить нельзя** — записи о
попытке просто нет. А именно её («не понял, не приступил») разбирать нужнее
всего.

### Почему не `student_notes` с видом `todo`

У заметки и у отметки разный срок жизни. «Не видит подобия» живёт в карточке
ученика годами, «разобрать задачу 2» гаснет после ближайшего урока. Смешать —
значит либо засорить карточку служебными записями, либо чистить руками.

Связь при этом сохраняем: в форме отметки галочка «записать и в карточку
ученика» создаёт рядом обычную `student_note`, её id ложится в
`student_note_id`.

## Экраны

### 1. Проверка домашки — `teacher.palomatika.ru/homework/assignment/{id}`

- На карточке каждой задачи — переключатель **«Разобрать»** рядом со статусом
  ВЕРНО/НЕВЕРНО. Одно нажатие, текст необязателен: проверяя дюжину задач,
  учитель поставит галочку, но не станет писать комментарий к каждой.
- Существующая форма заметки работает как раньше; если задача отмечена, текст
  дополнительно цепляется к пункту разбора.
- В шапке — счётчик «К разбору: N».
- Задачи со статусом «Неверно» подсвечиваются как кандидаты, но **не
  отмечаются автоматически**: выбор за учителем.
- Пункты в статусе `done` показываются серым следом «разобрано 14.08».

### 2. Подготовка урока — `pwa.teacher.lesson-prep`

Блок «К разбору» над пикером задач: `pending`-пункты, сгруппированные по
участникам урока. Чекбоксы, кнопка «Добавить в урок» → `planned` +
`lesson_session_id`.

Автоподстановка сознательно не делается: групповой урок с тремя учениками
превратится в кашу из дюжины карточек.

### 3. Урок, экран учителя

Панель «Разбор (N)» рядом со списком задач: условие, эталонный ответ, что
ответил ученик, миниатюры тетради (просмотрщик фото уже есть на странице
проверки — переиспользуем), заметка учителя.

### 4. Урок, экран ученика

Блок «Разбор» над задачами урока: условие, своё фото, только чтение.
Видимость — как у персональных задач урока (`assigned_student_id` /
`LessonSessionTask::visibleTo()`): ученик видит **только свои** пункты.

## Гашение

`LessonSessionService::end()` переводит все `planned`-пункты этой сессии в
`done` и проставляет `resolved_at`. Отдельного действия учителя не требуется.

## Безопасность

Единственное место, где можно случайно открыть чужую тетрадь.

Маршрут `pwa.teacher.homework.solution-photo` защищён проверкой
`canReviewHomework` и ученику недоступен. Ученического маршрута к фото сегодня
нет вообще — ученик фото только загружает.

Нужен новый маршрут `pwa.student.homework.solution-photo` с проверкой:
фото → submission → assignment → `assignment.student_id === auth()->id()`.
Никаких послаблений «по id урока» или «по токену» — только принадлежность
домашки самому ученику. Проверку покрыть тестом, включая negative-case с чужим
фото.

Сами фото секретом не являются (решение Стаса от 2026-08-13) — ограничение
ровно одно: ученик видит только свою домашку.

## Что сознательно не делается

- Разбор не показывается родителю.
- Аналоги из банка не подтягиваются (`LessonHomeworkSuggestionService` это
  умеет — можно приделать отдельно).
- «Текущая карточка» и синхронизация экранов не вводятся.
- `lesson_session_tasks`, live-грид, подсчёт решённых и «следующая задача» не
  трогаются.
- `bank`/`refs` в `homework_topic_tasks` не добавляются: разбор их не требует.
