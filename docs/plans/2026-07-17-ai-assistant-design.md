# AI-ассистент учителя — дизайн v1

> Дата: 2026-07-17. Одобрено Стасом (все ключевые развилки). Статус: дизайн готов, реализация ждёт API-ключ.

## Роль v1

**Запись + память.** Учитель во время урока коротко фиксирует наблюдения об учениках,
бот (DeepSeek) превращает их в структурированные записи и складывает в профиль ученика.
Оттуда можно доставать (лёгкий recall в чате + список в карточке). **Не** полноценный
собеседник-аналитик — это следующая итерация.

## Решённые развилки

- **Роль:** запись + память (не conversational-analyst).
- **Формат записей:** текст + авто-теги (тема/навык + тип: weakness/strength/todo/general).
- **Приватность:** анонимно — имя ученика вырезаем перед отправкой в API; ФИО/школа/контакты не уходят никогда.
- **Место:** чат-блок на странице урока (заменяет блок «Заметка»), контекст = участники урока.
- **Подтверждение:** запись сохраняется сразу; неверную можно удалить/поправить (без обязательного confirm).
- **Объём:** сразу весь чатбот (LLM function-calling), не поэтапно.
- **Механизм:** function-calling (вариант A).

## Провайдер

DeepSeek по умолчанию: `deepseek-chat`, OpenAI-совместимый Chat Completions + tool calling,
очень дёшево (доли копейки за запись). Конфиг в `config/services.php` (`base_url`, `model`, `api_key`
через env), ключ в `.agent-secrets/deepseek.env` (на прод — env-переменная). Обёртка
`app/Services/AssistantService.php` поверх Laravel `Http`. Переключение на Kimi (Moonshot,
тоже OpenAI-совместимый) — сменой env, без правок кода.

**Блокер реализации:** ключа DeepSeek в секретах пока нет — Стас заводит аккаунт и даёт ключ.

## Данные

**`student_notes`** — «база по ученикам» поверх авто-аналитики (`student_topic_mastery`):
- `student_id` FK, `teacher_id` FK
- `lesson_session_id` nullable FK (если запись из урока)
- `task_ref` nullable (bank+refs — если с кнопки «не понимает»)
- `topic_tag` nullable (строка: тема/навык, напр. «геометрия: подобие»)
- `kind` enum(`weakness`,`strength`,`todo`,`general`)
- `body` text (текст наблюдения)
- `source` enum(`chat`,`lesson_button`,`manual`)
- `created_at`
- индексы: (student_id, kind), (teacher_id)

**`lesson_assistant_messages`** — лог чата на урок (чтобы диалог пережил перезагрузку):
- `lesson_session_id` FK, `role` enum(`teacher`,`assistant`), `content` text, `created_at`

Общие заметки урока (не про конкретного ученика) бот пишет в существующее `lesson_sessions.note`
через инструмент `add_lesson_note` (append).

## Инструменты (function-calling)

Определяем для модели tools:
- `record_observation(participant_ref, kind, topic_tag, body)` — создаёт `student_notes`.
- `add_lesson_note(body)` — дописывает в `lesson_sessions.note`.
- `answer_about_student(participant_ref)` — сервер отдаёт модели записи ученика для ответа (recall).

Модель возвращает tool_calls; сервер исполняет и создаёт записи / формирует ответ.

## Поток (чат на уроке)

1. Учитель пишет: «Петя опять путает признаки подобия».
2. Сервер резолвит «Петя» → участник урока (по ростеру), присваивает placeholder (P1).
3. Анонимизация: наружу уходит «ученик путает признаки подобия» + справочник тем ОГЭ + tools.
4. DeepSeek → `record_observation(P1, weakness, "геометрия: подобие", "путает признаки подобия")`.
5. Сервер разворачивает P1 → student_id, создаёт `student_notes`, пишет ответ бота:
   «Записал Пете: подобие — западает 🔴».
6. Сообщения (реплика учителя + ответ бота) сохраняются в `lesson_assistant_messages`.

## «Не понимает» с урока (без LLM)

На активном уроке клик по задаче → выбор ученика → «не понимает» → сразу `student_notes`
(`source=lesson_button`, `task_ref` и `topic_tag` из задачи, `kind=weakness`). Отдельный
эндпоинт, LLM не нужен (структура уже известна).

## Recall

- В чате урока «что у Пети западало?» → `answer_about_student` → бот отвечает по записям.
- Карточка ученика (`student-profile`): новая секция «Наблюдения» — список `student_notes`
  с фильтром по типу/теме; каждую можно удалить/поправить.

## Приватность

Аноним-прослойка перед КАЖДЫМ вызовом API: заменяем имена участников на placeholder'ы,
разворачиваем обратно в ответе. Наружу — только текст наблюдения + справочник тем. ФИО,
школа, контакты, id — не отправляем. Документируем в модуле.

## Ошибки/устойчивость

- API упал/таймаут/невалидный ответ → сохраняем сырой текст как `student_notes(kind=general,
  source=chat)` без тегов + ответ бота «не разобрал, сохранил как есть». Ничего не теряется.
- Таймаут HTTP ~15с; ретрай 1 раз.
- Ключ не задан → чат отвечает «ассистент не настроен», кнопка «не понимает» работает (без LLM).

## UI

- **Урок (`lesson-prep`):** блок «Заметка» заменяется на чат-ассистент (лента сообщений +
  поле ввода). Быстрая кнопка «не понимает» — на задаче в live-гриде (клик → выбор ученика).
- **Карточка ученика:** секция «Наблюдения» (записи с тегами, фильтр, удалить/править).

## Эндпоинты

- `POST /lessons/{id}/assistant` `{message}` → прогон через LLM, создаёт записи, возвращает ответ + новые записи. (teacher, своя сессия)
- `GET /lessons/{id}/assistant` → история сообщений (для рендера/polling).
- `POST /lessons/{id}/dont-understand` `{student_id, task_id}` → быстрая запись без LLM.
- `PATCH/DELETE /student-notes/{id}` → правка/удаление записи.
- (карточка ученика уже есть — добавить рендер записей.)

## Тесты

- LLM мокаем `Http::fake`: фраза → корректный tool-call → создаётся `student_notes` с тегами.
- Анонимизация: имя реально вырезано из payload перед отправкой (assert на `Http::fake` запрос).
- «Не понимает» создаёт запись без обращения к API.
- Recall: `answer_about_student` возвращает записи ученика.
- Ошибка API → сырой fallback-нот, ничего не потеряно.
- Доступ: чужая сессия → 403; запись чужого ученика не редактируется.
- Реальный API в тестах не дёргаем.

## Не в v1 (потом)

Полноценный собеседник-аналитик, кросс-ученические сводки, автосоветы по ДЗ,
редактирование записей через чат, голосовой ввод, суммаризация урока.
