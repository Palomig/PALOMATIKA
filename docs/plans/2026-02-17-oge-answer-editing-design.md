# Дизайн: правка ответов ОГЭ 06/07 и расширение "Проверка ОГЭ"

**Дата:** 2026-02-17
**Статус:** Approved
**Контекст:** статичная база заданий из PDF, без генерации задач

## Цели

1. Добавить/уточнить ответы для заданий ОГЭ `06` и `07` в базе.
2. Расширить систему "Проверка ОГЭ" так, чтобы можно было редактировать ответ примера и сразу обновлять базу.
3. Ограничить доступ:
- к базе заданий: только `teacher` и `admin`.
- к редактированию ответов: только `admin`.
4. Отображать у ответа источник и автора в компактном формате справа:
- `AI`
- `Ручной by {Имя}`

## Подтверждённые решения

### 1) Архитектурный подход

Выбран вариант `DB-overrides + аудит`:
- JSON-файлы в `storage/app/tasks/topic_*.json` остаются базовым источником контента.
- Ручные правки ответов хранятся в БД как override по `task_key`.
- На чтении приоритет у override; если override нет, используется базовый ответ из JSON.

Причины выбора:
- безопасное одновременное редактирование;
- отслеживаемость, кто и когда менял;
- отсутствие прямых race-condition на файловой системе.

### 2) Политика доступа

- Просмотр тем и API данных тем: `auth + role:teacher,admin`.
- Изменение ответов: `auth + role:admin`.

### 3) Источник ответа (provenance)

- Все текущие ответы в статичной базе по умолчанию считаются `AI`.
- Любая правка админом переводит ответ в `Ручной`, и фиксируется автор изменения.

## Данные и хранение

### Таблица `task_answer_overrides`

Назначение: текущее актуальное override-значение ответа.

Поля:
- `id`
- `task_key` (unique), формат: `topic_06_block_1_zadanie_2_task_4`
- `answer` (string)
- `source` (`manual` | `ai`), для ручной правки используется `manual`
- `updated_by_user_id` (FK -> users.id)
- `created_at`, `updated_at`

### Таблица `task_answer_override_logs`

Назначение: журнал изменений.

Поля:
- `id`
- `override_id` (FK -> task_answer_overrides.id)
- `old_answer`
- `new_answer`
- `changed_by_user_id` (FK -> users.id)
- `created_at`, `updated_at`

## UI/UX поведение

### Отображение ответа

В блоке ответа показывается:
- сам ответ;
- справа компактный бейдж источника:
  - `[AI]`
  - `[Ручной by Ivan]`

### Редактирование (только admin)

- У ответа появляется кнопка `✏️`.
- По клику открывается inline-редактор.
- После сохранения ответ обновляется сразу (без перезагрузки) и бейдж меняется на ручной с именем админа.

## API контракт

### `PATCH /api/topics/{topicId}/answers`

Доступ: `auth + role:admin`.

Request body:
- `task_key` (required, string, валидный формат и принадлежность теме)
- `answer` (required, string, non-empty, ограничение по длине)

Успех (`200`):
- `task_key`
- `answer`
- `source` (`manual`)
- `source_label` (`Ручной by ...`)
- `updated_by_name`

Ошибки:
- `403` — не admin;
- `404` — задача не найдена в теме;
- `422` — ошибка валидации.

## Поток данных

1. Пользователь открывает тему `06`/`07` (teacher/admin).
2. Сервер отдаёт задачи из JSON.
3. Сервис ответов мержит overrides из БД (если есть).
4. Шаблон рендерит `Ответ + бейдж источника`.
5. Admin при сохранении правки вызывает `PATCH`.
6. Сервер делает upsert override + пишет лог.
7. Клиент обновляет отображение ответа и бейджа.

## Error handling

- Невалидный `task_key` или пустой ответ: не писать в БД, вернуть `422`.
- `task_key` не принадлежит `topicId`: вернуть `404`.
- Ошибка БД: вернуть `500` с безопасным сообщением.

## Тестовая стратегия

### Feature
- `teacher`/`admin` имеют доступ к `/topics`, `student` не имеет.
- `admin` может обновить ответ через `PATCH`, `teacher` не может.
- После `PATCH` при чтении темы отображается override-ответ и бейдж ручного источника.

### Unit
- Резолвер ответа берёт override при наличии.
- Без override использует базовый JSON-ответ как `AI`.
- Формат source label корректен (`AI`, `Ручной by Name`).

## Нефункциональные требования

- Обратная совместимость: темы без override продолжают работать без изменений JSON.
- Минимальные изменения UI: расширяем существующий блок ответа и review-tool поведение.
- Безопасность: server-side проверка прав и валидация обязательны.

## Результат внедрения

- Статичная база 06/07 остаётся каноничным контентом.
- Ошибки ответов исправляются мгновенно админами в защищённом режиме.
- У каждого ответа прозрачно видно происхождение (`AI` или `Ручной by ...`).
