# Приложение для родителей + Диагностика — Обзор

## Что строим

Два новых модуля в рамках одного Laravel-бэкенда:

1. **Диагностический тест** — встраивается в Mini App ученика. Новый ученик после онбоардинга проходит тест, который прощупывает каждый навык (сложение дробей, умножение дробей, теорема Пифагора и т.д.) и выставляет начальные веса в системе скиллов.

2. **Приложение для родителей** — отдельный продукт с тремя точками входа:
   - Telegram Mini App (через отдельного бота `@palomatika_parent_bot`)
   - Android SDK-приложение
   - Веб-сайт (для iPhone-пользователей, у которых может быть заблокирован Telegram)

Все три фронтенда работают на одном бэкенде. Как Uber и Uber Driver — два приложения, одна база.

---

## Что уже готово

- **60 навыков** в иерархическом дереве (Алгебра → Сложение дробей, Умножение дробей... / Геометрия → Теорема Пифагора, Синус... / Практика → Вероятность, Статистика...)
- **Модели и таблицы** `skills`, `user_skills`, `skill_dependencies` — схема есть, но `user_skills` пустая (никто не проходил диагностику)
- **API для навыков** — эндпоинты уже работают (`/api/skills`, `/api/skills/progress`)
- **Расписание уроков** — таблица `lesson_schedule`, Evrium-бот уже с ней работает
- **Система ДЗ** — учитель задаёт через Mini App, ученик получает

## Чего не хватает

- Роль `parent` в системе пользователей
- Таблица связки родитель↔ученик
- Таблица посещаемости (Evrium-бот знает кто пришёл, но данные некуда записывать)
- Диагностический тест (заполняет скиллы)
- Весь фронтенд для родителей
- Уведомления родителям

## Фаза 1 — Фундамент БД

**Что делаем:**
- Добавляем роль `parent` в enum ролей пользователей
- Создаём таблицу `parent_student` — связка родитель↔ученик (many-to-many, т.к. у ребёнка может быть мама и папа, а у родителя — несколько детей)
- Создаём таблицу `lesson_attendance` — запись посещаемости (пришёл/не пришёл/опоздал/отменён), заполняется Evrium-ботом

**Почему отдельная таблица для посещаемости, а не колонка в расписании:**
Расписание — это шаблон (вторник 15:00), а посещаемость — факт конкретной даты. Один слот расписания порождает десятки записей посещаемости за учебный год.

## Фаза 2 — Диагностический тест

Диагностический тест — это **статичный, вручную составленный** набор заданий. Не случайная выборка из базы, а конкретные задания, выбранные учителем через веб-редактор.

### 2а. Редактор диагностического теста (для учителя/админа)

Веб-интерфейс на `/tg/teacher/diagnostic-editor` (или `/admin/diagnostic`), где учитель:

1. Видит список всех навыков (дерево: Алгебра → Сложение дробей, Умножение дробей...)
2. Для каждого навыка может выбрать конкретные задания из банка ОГЭ (через браузер заданий)
3. Может добавлять задания не ко всем навыкам — только к тем, которые хочет проверить
4. Может менять порядок вопросов drag-and-drop
5. Может указать, какой навык проверяет каждый вопрос (привязка задание↔навык)
6. Сохраняет тест — он становится единственным диагностическим тестом для всех новых учеников

**Хранение:** JSON-файл `storage/app/diagnostic_test.json` или запись в таблице `diagnostic_tests`. Тест один, статичный, пока учитель не отредактирует.

**Интерфейс редактора:**
```
┌─────────────────────────────────────────────────────────┐
│  Редактор диагностического теста                        │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  Навык: Сложение дробей                                │
│  ┌─ Вопрос 1: "Вычислите: 1/3 + 2/5"  [Удалить]       │
│  └─ Вопрос 2: "Найдите: 3/7 + 1/14"   [Удалить]       │
│  [+ Добавить задание из банка]                         │
│                                                         │
│  Навык: Умножение дробей                               │
│  ┌─ Вопрос 3: "Вычислите: 2/3 × 5/6"  [Удалить]       │
│  [+ Добавить задание из банка]                         │
│                                                         │
│  Навык: Теорема Пифагора                               │
│  (нет заданий)                                         │
│  [+ Добавить задание из банка]                         │
│                                                         │
│  [Сохранить тест]                                      │
└─────────────────────────────────────────────────────────┘
```

При нажатии «Добавить задание из банка» — открывается модалка с выбором темы ОГЭ → блока → задания (те же данные из `TaskDataService`).

### 2б. Прохождение теста учеником

**Поток:**
```
Онбоардинг → Диагностика (обязательно) → Дашборд
```

Ученик видит задания из составленного теста одно за другим. После прохождения — результаты записываются в `user_skills` с весами на основе правильности ответов.

Если ученик уже прошёл диагностику — пропускается.

Результаты показываются как дерево навыков с цветовой кодировкой:
- 🟢 Зелёный (>70%) — сильный навык
- 🟡 Жёлтый (50-70%) — средний
- 🔴 Красный (<50%) — слабый, нужна тренировка

**Количество вопросов:** определяется учителем в редакторе. Рекомендуемо 20-40 вопросов (~10-20 минут).

## Фаза 3 — Приложение для родителей

**Авторизация:**
- Отдельный Telegram-бот (`@palomatika_parent_bot`)
- Та же HMAC-верификация, что и у учеников, но с другим токеном бота
- При первом входе создаётся пользователь с ролью `parent`
- Привязка к детям — вручную через artisan-команду `parent:link`

**Экраны:**

### Дашборд
Карточки детей. На каждой:
- Имя ребёнка
- Средний уровень навыков (0-100%)
- Количество слабых навыков
- Последнее посещение урока
- Количество невыполненных ДЗ
- Прошёл ли диагностику

### Навыки ребёнка
Дерево навыков с прогресс-барами, сгруппированное по категориям:
```
📐 Алгебра
  Сложение дробей        ████████░░  80%
  Умножение дробей       ███░░░░░░░  30%  ← слабо!
  Деление дробей         █████░░░░░  50%

📏 Геометрия
  Теорема Пифагора       █████████░  90%
  Подобие треугольников  ██░░░░░░░░  20%  ← слабо!
```

### Посещаемость
Список/календарь с цветными отметками:
- 🟢 Присутствовал
- 🔴 Отсутствовал
- 🟡 Опоздал
- ⚪ Отменён

Статистика: всего уроков, процент посещаемости.

### Домашние задания
Список ДЗ со статусами:
- ✅ Выполнено
- ⏳ В процессе
- ❌ Не выполнено
- ⚠️ Просрочено

## Фаза 4 — API для Android

Те же данные, что и в веб-версии, но в формате JSON:
```
GET  /api/parent/children                  — список детей
GET  /api/parent/child/{id}/skills         — навыки ребёнка
GET  /api/parent/child/{id}/attendance     — посещаемость
GET  /api/parent/child/{id}/homework       — ДЗ
```
Авторизация через Sanctum-токен.

---

## Фаза 5 — Интеграция с Evrium-ботом

Новый эндпоинт `POST /api/attendance`, который Evrium-бот вызывает при начале урока:
```
"Ученик Петя пришёл на урок 2026-03-23 в 15:00"
→ запись в lesson_attendance
→ уведомление родителю
```
Защищён тем же `X-Deploy-Secret`, что и остальные deploy-эндпоинты.

## Фаза 6 — Уведомления

**Принцип:** уведомления не должны надоедать. Только важные события, без спама.

Сервис `ParentNotificationService`:
- Если родитель на Android → push через Firebase (TODO, заготовка)
- Если через Telegram → сообщение от `@palomatika_parent_bot`

**Только два триггера:**

1. **Ребёнок не пришёл на урок** — отправляется уведомление, НО только если у ученика нет статуса «Болеет»
2. **Ребёнок не сделал ДЗ** — отправляется после дедлайна, если ДЗ не выполнено

**НЕ отправляем:**
- «Ребёнок пришёл на урок» — это нормальная ситуация, не нужно спамить
- «ДЗ задано» — родителю это не нужно знать каждый раз

### Статус «Болеет»

Новое поле у ученика: `sick_until` (дата). Пока дата не прошла:
- Уведомления о посещаемости НЕ отправляются родителю
- В приложении родителя отображается бейдж «Болеет до ДД.ММ»
- В посещаемости пропуски помечаются как «Болезнь» вместо «Отсутствовал»

**Кто может поставить/снять:**
- Учитель — через интерфейс ученика в Mini App учителя
- Родитель — через своё приложение
- Оба могут снять досрочно

## Фаза 7 — Привязка родитель↔ученик

Привязка должна работать через два канала:

### 1. Artisan-команда (для ручного запуска)
```
php artisan parent:link 42 15 --relation=mother
```
Где 42 — ID родителя, 15 — ID ученика.

### 2. API-эндпоинт для Джарвиса
```
POST /api/parent/link
{
    "parent_id": 42,
    "student_id": 15,
    "relation": "mother"
}
```
Защищён `X-Deploy-Secret`. Джарвис сможет привязывать родителей к ученикам через этот эндпоинт, не заходя на сервер.

Оба способа добавляются в whitelist для удалённого запуска через deploy API.

## Порядок реализации

```
Фаза 1 (БД)  →  Фаза 2 (Диагностика)  →  можно деплоить ученикам
                         ↓
              Фаза 3-4 (Родительское приложение)  →  Фаза 5-6 (Посещаемость + уведомления)  →  Фаза 7 (Привязка)
```

Фазы 1-2 — фундамент, без них ничего не работает.
Фазы 3-7 можно делать параллельно после фундамента.

## Что НЕ входит в этот план

- Пазлы (система сборки решения из блоков) — отдельная большая фича
- Decay (затухание весов неиспользуемых навыков) — можно добавить позже cron-задачей
- Firebase FCM push — заготовка есть, но настройка Firebase — отдельная задача
- Дизайн Android-приложения — только API, фронт на Android делается отдельно
- Skill dependencies (пререквизиты навыков) — таблица есть, но логика блокировки не реализуется сейчас
