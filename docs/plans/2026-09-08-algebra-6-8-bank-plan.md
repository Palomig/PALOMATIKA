# Algebra 6–8 Bank Implementation Plan

**Goal:** Наполнить проверенный банк навыков с шестью уровнями и комбинациями и подключить к существующему уроку.

**Architecture:** Единый каталог навыков и стабильных заданий, детерминированные фабрики с независимой математической проверкой. Адаптер сохраняет чтение старого alg-skill, конструктор уроков получает фильтры уровней и сочетаний; исторические снимки не меняются.

**Tech Stack:** Laravel/PHP, JSON, Node.js для генерации, Python/SymPy для независимой проверки, Blade/Alpine для существующего конструктора.

Дизайн: `2026-09-08-algebra-6-8-bank-design.md`. Этот документ описывает последующую реализацию; текущий результат — карта и дизайн. Перед кодом использовать test-driven-development, перед изменением интерфейса — соответствующие frontend-навыки. Работа в отдельном worktree от свежего origin/main; доставка по действующей процедуре проекта.

## 1. Инвентаризация и сопоставление

Файлы: читать `storage/app/tasks/alg/grade_7/skills.json`, `scripts/generate-grade7-skill-bank.mjs`; создать `docs/algebra-bank/legacy-mapping.md`.

1. Для каждого из 78 старых навыков сопоставить позиции A001–A156 нового каталога.
2. Отметить геометрические сюжеты, кубы и системы с тремя переменными как вне основного объёма. Не удалять старые ссылки.
3. Просмотреть по одному примеру каждой конструкции и граничные коэффициенты; записать reuse/rework/exclude.
4. Сохранить старые идентификаторы в таблице соответствий, не менять данные действующего банка.
5. Коммит: `docs: map legacy algebra tasks to skill catalog`.

## 2. Каталог и контракт пилота

Создать `storage/app/tasks/alg/catalog/skills.json`, `storage/app/tasks/alg/catalog/templates.json`, `scripts/algebra-bank/validate.mjs`, `tests/js/algebra-bank-schema.test.mjs`.

1. Добавить проверку неизвестного skill_id, отсутствующего primary_skill_id, difficulty вне 1–6, повторного task ID и циклов prerequisites.
2. Запустить `node --test tests/js/algebra-bank-schema.test.mjs`; ожидается отказ до реализации валидатора.
3. Реализовать валидатор контракта из дизайна; каталог хранит понятные slug наряду с A-ID.
4. Проверить плохие фикстуры и корректную смешанную задачу: один ID, три тега, одна основная цель.
5. Повторить команду; ожидается PASS. Коммит: `feat: define algebra bank catalog contract`.

## 3. Пилотные фабрики и независимые ответы

Создать `scripts/algebra-bank/generate.mjs`, `scripts/algebra-bank/factories/brackets.mjs`, `equations.mjs`, `powers.mjs`, `mixed.mjs` в том же каталоге factories; `scripts/algebra-bank/verify.py`, `tests/js/algebra-bank-generation.test.mjs`, `tests/python/test_algebra_bank_math.py`.

1. Зафиксировать перечень конструкций трёх семейств по уровням до генерации чисел; добавить текстовые обратные задания с ручным решением.
2. Написать тесты воспроизводимости seed, уникальности, отсутствия деления на ноль и вырождения заявленного типа.
3. Запустить `node --test tests/js/algebra-bank-generation.test.mjs`, получить ожидаемые ошибки отсутствующей реализации.
4. Реализовать фабрики с точной рациональной арифметикой. Условие и ответ сохранять в опубликованном наборе, не генерировать при открытии урока.
5. Написать независимую проверку уравнений, множества корней, равенства выражений и ОДЗ. Включить испорченные ответы, которые проверка обязана отклонить.
6. Запустить `python3 -m unittest discover -s tests/python -p 'test_algebra_bank_math.py'` и JS-тест; ожидается PASS.
7. Сформировать обзор всех конструкций и краевых случаев для математической и педагогической проверки; только прошедшим поставить verified.
8. Коммит: `feat: add verified algebra pilot factories`.

## 4. Чтение и совместимость урока

Изменить `app/Services/AlgTaskDataService.php`, `app/Services/LessonTaskPickerService.php`; создать `tests/Unit/AlgebraSkillCatalogTest.php`; расширить `tests/Unit/LessonTaskPickerServiceTest.php`.

1. Протестировать чтение старых simple/medium/high и новых уровней 1–6, поиск по всем выбранным тегам и дедупликацию смешанной задачи.
2. Запустить `php artisan test --filter='AlgebraSkillCatalogTest|LessonTaskPickerServiceTest'`, убедиться в ожидаемых сбоях новых сценариев.
3. Реализовать адаптер единого каталога, фильтры класса/всех классов, навыков и уровней; старые ID разрешать без изменения.
4. Проследить текущий resolver добавления задачи на урок от picker до снимка; сохранить новый stable ID и метаданные в совместимом формате. Конкретный обработчик определить поиском вызовов picker, не вводить параллельный путь создания урока.
5. Добавить интеграционную проверку старого и нового задания в уроке: условие, ответ и режим ручной проверки сохраняются после изменения каталога.
6. Повторить целевые PHP-тесты; ожидается PASS. Коммит: `feat: expose algebra catalog in lesson picker`.

## 5. Интерфейс выбора

Изменить `resources/views/pwa/teacher/lesson-prep.blade.php`, `resources/views/alg-skills/index.blade.php`, `resources/views/alg-skills/show.blade.php`, `resources/views/alg-skills/partials/level.blade.php` и фактический JS-компонент picker, если вынесен из Blade.

1. Показать шесть уровней из данных, дополнительные теги и режим проверки на карточке.
2. Добавить подбор сочетания с явной семантикой «все навыки»; хранить выбранные задания при изменении фильтра.
3. Показать конструкции отдельно от числовых вариантов по template_id.
4. Проверить в браузере на телефоне и десктопе: базовый навык, комбинация, пустая выборка, ручная проверка, добавление и открытие учеником.
5. Проверить, что ответы доступны учителю, а ученик не видит их до предусмотренного этапа проверки.
6. Коммит: `feat: add six-level algebra selection UI`.

## 6. Наполнение и публикация

1. По пилоту измерить реальное разнообразие и число пригодных вариантов; уточнить ориентир 6–10 тысяч задач.
2. Наполнять волнами: арифметика → многочлены/ФСУ → дроби/корни/уравнения 8 → функции/системы/неравенства/текст.
3. Каждую фабрику проверять по математическим инвариантам и обзорной выборке; комбинации не считать повторно в общем объёме.
4. Перед доставкой выполнить целевые тесты банка и уроков, сохранить отчёт с количеством published/verified/draft и известными ограничениями.
5. По действующей инструкции доставки проекта опубликовать проверенную версию и проверить урок/домашку. Не считать push публикацией.

Критерии завершения: перечислены в дизайне. Новая аналитика mastery, автодиагностика и геометрия не входят в этот план.
