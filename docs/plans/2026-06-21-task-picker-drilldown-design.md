# Drill-down task picker для урока и домашки — дизайн

> Дата: 2026-06-21. Статус: согласован, готов к плану реализации.

## Проблема

Сейчас выбор задач из банков на уроке ([lesson-prep.blade.php](../../resources/views/pwa/teacher/lesson-prep.blade.php))
— это ряд выпадающих `<select>`: кнопки банка → select класса → длинный select
темы/навыка → плоский список карточек. Неудобно: **не видно «что внутри темы»,
пока её не выберешь**, выбор «банка» — лишняя для учителя абстракция. В домашке
(`topic_photo_practice`) — отдельный, ещё более узкий поток.

## Цель

Заменить «ряд селектов» на **drill-down мастер с визуальными полосками** (как 2-я
часть банка заданий): на каждом шаге видно содержимое — у полоски сразу показан
один пример. Один общий компонент для урока и домашки.

## Вводные (согласовано)

| Уровень | 7/8 класс | 9 ОГЭ |
|---|---|---|
| Банк (скрыт от учителя) | `alg-skill` | `oge` |
| Полоски | навыки | темы |
| Внутри полоски | 3 уровня сложности (simple/medium/high) | блоки/задания |
| Финал | отметка отдельных карточек-задач (как сейчас) | то же |

- Верхний уровень = **класс**, понятие «банк» скрыто.
- Один общий picker для урока и домашки.
- Хранилище (`homework_topic_tasks`, lesson session tasks), резолвинг и проверка
  ответов — **не трогаем**.

## Подход

**Drill-down мастер с хлебными крошками** (отвергнут аккордеон на одном экране —
теряются полоски и распухает экран на ОГЭ).

## Секция 1 — структура полоски и «1 пример»

Полоска = горизонтальная строка: слева title, справа один пример-формула, мелкий
счётчик задач.

```
┌─────────────────────────────────────────────────────────┐
│  3. Раскрытие скобок              2(x−3)+5 =      · 24 зад│
└─────────────────────────────────────────────────────────┘
```

Источник «1 примера»:
- Навык (7/8): первая задача из `representative_tasks` навыка → `expression`.
- Тема (ОГЭ): первая `supported`-задача темы (через существующий `supportedTasks()`).
- Рендер формулы — тем же `renderLatex`, что и карточки задач (визуальный паритет).
- Фолбэк: SVG-тумбнейл → обрезанная инструкция → «(без примера)».

Бэкенд: в `LessonTaskPickerService::topics()` и `::skills()` добавить поле
`preview` (`expression` + опц. `image_svg`). Сейчас отдают только `id/slug/title`.

## Секция 2 — навигация и состояние

Один Alpine-компонент, конечный автомат. Поле `step` + накопительный `refs`.

```
step = 'class'   → плитки классов            [7] [8] [9 ОГЭ]
   ↓ класс → определяем банк (скрыто)
step = 'strips'  → полоски (навыки/темы) + «1 пример»
   ↓ полоска
step = 'buckets' → уровни сложности (7/8) ИЛИ блоки/задания (ОГЭ)
   ↓ уровень/блок
step = 'tasks'   → карточки задач с чекбоксами → «Добавить (N)»
```

Маппинг класс → банк (единственное место «скрытого банка», расширяемая таблица в
конфиге компонента):

| Класс | bank | refs |
|---|---|---|
| 7 | `alg-skill` | `grade=7` |
| 8 | `alg-skill` | `grade=8` |
| 9 ОГЭ | `oge` | — |

Навигация:
- Хлебные крошки сверху — предыдущие шаги кликабельны, сбрасывают `refs` ниже.
- Кнопка «← назад» = шаг назад.
- `selected` копится поверх шагов; счётчик «Добавить (N)» виден всегда.
- Данные каждого шага кешируются в памяти компонента.

Эндпоинт — текущий `GET /lessons/picker-options` (уже параметризован
`bank/grade/topic_id/zadanie_number/skill_slug/level_id`); меняется только то, что
полоски несут `preview`.

## Секция 3 — общий компонент в уроке и домашке

Picker ничего не знает про урок/домашку. Проводит по шагам и на «Добавить (N)»
эмитит наружу массив выбранных `refs`.

```
resources/views/pwa/_shared/task-picker.blade.php   ← разметка
public/js/task-picker.js (или inline Alpine)        ← taskPicker({ onAdd })
```

Контракт наружу — один колбэк `taskPicker({ onAdd(refs[]) })`:
- Урок (`lesson-prep`): `onAdd` → существующий `addSelectedTasks` (POST в сессию).
- Домашка (`topic_photo_practice`): `onAdd` → в черновик ДЗ; на сохранении каждая
  `ref` резолвится `TaskBankResolver::resolve()` в снапшот `task_payload` +
  `correct_answer`.

`TaskBankResolver` уже принимает эти `refs` (`oge`/`alg-skill`) — общий формат
выбора подходит обоим потокам без переделки хранения.

Меняется по сути: старый «ряд селектов» в lesson-prep → `@include` общего
партиала; домашка получает тот же `@include`.

## Секция 4 — крайние случаи, ошибки, тестирование

Крайние случаи:
- Пустая полоска (нет поддерживаемых задач) — не показываем (фильтр уже в
  `supportedTasks()`/`zadaniya()`).
- Нет «1 примера» — фолбэк (см. секцию 1).
- Класс без банка в маппинге (будущий «8 ОГЭ») — шаг `strips` показывает «Скоро».
- Дубли — уже добавленная задача помечена «уже добавлено», дедуп по `uid`/`refs`.
- Резолв упал на сохранении (задача исчезла из JSON) — ловим `DomainException`,
  «задача больше недоступна», пропускаем.

Ошибки: сетевой сбой шага → инлайн «повторить», выбранные задачи не теряются.

Тестирование:
- Unit: `topics()/skills()` содержат `preview`; пустые темы отфильтрованы; маппинг
  класс→банк корректен для 7/8/9.
- Резолв-roundtrip: `refs` из picker'а → `TaskBankResolver::resolve()` не бросает
  для всех видимых задач.
- Ручной мокап-прогон на dev-сборке (показать макетом, не катить сразу на прод).
