# Банки заданий — карта всех 3 направлений

> Дата скана: 2026-05-03. Цифры по объёму получены прохождением по `storage/app/tasks/`.

## Принципы (общие для всех 3 направлений)

1. **Источник истины** — JSON в `storage/app/tasks/`. Никаких захардкоженных данных в контроллерах.
2. **Номера = номера в PDF.** Нельзя менять для красоты.
3. **SVG, не PNG.** PDF-изображения в `docs/oge_data/images/` и `docs/ege_data/images/` — только референс.
4. **`*_geometry.json`** — это **источник** для геометрии. `topic_XX.json` со встроенными SVG **генерируется** через `php artisan svg:bake {id}` (или `svg:bake-ege`). Вручную `topic_XX.json` для геометрических задач **не редактируем**.
5. **TaskDataService / EgeTaskDataService / VprTaskDataService** — единственный путь чтения банков из кода.

> **Выбор задач в урок/ДЗ** — единая точка входа: общий drill-down picker `resources/views/pwa/_shared/task-picker.blade.php` (класс → полоски навыков/тем с «1 примером» → уровень/блок → задачи). Опции отдаёт `LessonTaskPickerService` (`/lessons/picker-options`), выбранные `{bank, refs}` резолвит `TaskBankResolver`. Банк скрыт за классом (7/8 → `alg-skill`, 9 ОГЭ → `oge`).

## ЕГЭ — переезд на банк ФИПИ (в работе)

Профиль ЕГЭ переносится из открытого банка ФИПИ — так же, как перенесли ОГЭ.
Решения: переносим **только профиль** (997 заданий), базовый уровень пока
остаётся сайтом `palomig.ru/ege-bank/`; сначала собираются ответы, потом
импорт; прежний ЕГЭ-банк при переключении помечается `palomatika_legacy` и
скрывается, но не удаляется — история ДЗ должна остаться читаемой.

| что | где |
|---|---|
| выгрузка | https://palomig.ru/ege-bank/export/ege_prof_katex.json |
| рисунки | https://palomig.ru/ege-bank/export/ege_prof_images.tar.gz |
| импорт | `php artisan tasks:import-fipi-ege --url=… --images=…` |

Тема в базе — **номер задания ЕГЭ** (01…19), задания внутри неё собираются
по подтипам банка: кураторской учебной карты, как у ОГЭ, для ЕГЭ нет.
Раскладка — 19 тем, 192 задания, 997 задач.

**Чертежи остаются картинками — решение Стаса от 2026-08-07.** Общий принцип
«SVG — основа проекта» на этот банк не распространяется: в ОГЭ каждый растр
заменён своим SVG, но их рисовали месяцами, а для ЕГЭ таких SVG нет, и без
чертежа условие нерешаемо. Файлы раскладываются в `public/ege-bank/img`; у
каждого растра класс `fipi-figure` (чертёж, белая подложка на тёмном фоне)
или `fipi-inline` (обозначение внутри предложения).

`EgeTaskDataService` читает тему из базы, а при её отсутствии — из JSON, как
раньше: выкладка кода и переезд данных независимы.

**Название задания — только из банка.** Карта `topicsMeta` в
`EgeTaskDataService` запасная, она работает лишь пока темы нет в базе, и
обязана совпадать с нумерацией ФИПИ. Своих карт в шаблонах быть не должно:
экраны ученика были скопированы с ОГЭ вместе с его списком тем, и №15
подписывался «Треугольниками», а №10 на витрине значился «Графиками», хотя
внутри открывалась «Текстовая задача». Название приходит с самой задачей
(`topic_title`). Подписи в базе правятся `php artisan tasks:refresh-ege-meta`
— переимпорт банка ради описания не нужен.

**Черновики.** Задачи без ответа (в профиле их 16) и непроверяемое «Да»
лежат со статусом `draft`. Фильтр `production` стоит по умолчанию в
`getRandomTasks`/`getRandomTasksFromZadanie` — иначе черновик попадал в
печатный вариант и в `/api/ege/{n}/random`. Редакторская витрина
`/ege/topics/{n}` показывает их намеренно, как и витрина ОГЭ.

**Банк подписан «(П)» — это профиль.** Базовый уровень (Б) добавится
отдельным банком, а до тех пор надпись «ЕГЭ» ни о чём не говорит: у учителя
в picker'е это «10–11 ЕГЭ (П)», у ученика — «База заданий ЕГЭ (П)», в
подписи добавленной на урок задачи — «ЕГЭ (П) · Тема … · Задание …».
Появится база — метка (Б) встаёт в те же места.

## ЕГЭ — база (Б), второй уровень рядом с профилем

Уровни ЕГЭ — два независимых проекта банка ФИПИ, и в Паломатике это **два
банка**: `ege` (профиль, 1–19) и `ege_b` (база, 1–21). Не разделы одного
банка: задание 12 у профиля — «Наибольшее и наименьшее значение», у базы —
планиметрия по рисунку. Общего у них только код: `EgeTaskDataService`
принимает уровень (`new EgeTaskDataService(EgeTaskDataService::LEVEL_BASE)`)
и подставляет банк, карту тем и ключ кеша; второго сервиса заводить нельзя —
копии карт названий уже расходились.

| что | где |
|---|---|
| выгрузка | https://palomig.ru/ege-bank/export/ege_base_katex.json |
| рисунки | https://palomig.ru/ege-bank/export/ege_base_images.tar.gz |
| сборка выгрузки | `fipi-sync: python3 export_ege_katex.py --level base --deploy` |
| приёмка | `fipi-sync: python3 verify_ege_export.py --level base` |
| импорт | `php artisan tasks:import-fipi-ege --level=base --url=… --images=…` |
| рисунки на проде | `public/ege-bank/img-base` (у профиля свой `img`) |

**Состояние на 2026-08-26: 7786 заданий в банке ФИПИ → 7762 в выгрузке (24
без рисунка, который ФИПИ не отдал) → 6816 задач в 538 заданиях 21 темы в
базе данных. 946 задач классификатор не отнёс ни к одному номеру и они не
импортируются.**

Ответы собираются отдельным слоем в `fipi-sync` (`compute_ege_answers.py
--level base` у Claude, контактные листы у Codex) и приезжают следующим
импортом — он идемпотентен. Готовы **5098 из 6816**, в 18 темах из 21.
Крупнейшее закрытое: 12 «Планиметрия» 1088/1212, 14 «Вычисления» 872/873,
15 «Проценты» 369/491, 13 «Стереометрия» 364/382, 17 «Уравнение» 341/353,
05 «Вероятность» 275/370, 16 «Степени» 255/274, 04 «Формула» 255/448, 11
«Объёмы» 227/236, 01 «Простейшая текстовая» 199/229, 10 «Планиметрия»
153/183, 03 «Чтение таблицы» 145/219, 09 «Площадь по клеткам» 121/121, 07
«Графики» 104/123.

Пустые пока: 06 «Выбор варианта» (таблицы тарифов и поставщиков), 08
«Логика» (63 подтипа) и 19 «Свойства чисел» — у последнего 216 заданий из
240 с открытым ответом и черновиками останутся. Остальные 1718 задач в
`draft`: ученику не показываются, в вариант не попадают. У учителя в
picker'е видны только темы с ответами — `supportedTasks` требует ответ, и
пустая вкладка ему ни к чему.

**Проверка ответов банка — дешёвая и обязательная:** у базового уровня
ответ всегда целое или конечная десятичная дробь. Пять иррациональных
ответов, приехавших с картиночной партией, нашлись именно так.

**217 заданий не получат ответа никогда** — «запишите какое-нибудь одно
такое число»: верных ответов много, автопроверка отвергла бы верный ответ
ученика. Они помечены `answer_kind='any_valid'` и остаются черновиками
(`UNVERIFIABLE_KINDS` в импортёре).

Работа над оставшимися поделена (решение Стаса от 26.08): **всё, где
условие в чертеже (`fipi-figure`), решает Codex** — 2339 заданий, из них
12 «Планиметрия» 1088, 13 «Стереометрия» 364, 11 «Объёмы» 227; ТЗ в
`fipi-sync/docs/ege-base-images-codex.md`. Текстовое и счётное остаётся за
Claude: 15 «Проценты» (489), 05 «Вероятность» (370), 06 «Выбор варианта»
(240), 19 «Свойства чисел» (240), 01, 20, 08, 02 и 946 заданий, которым
классификатор не дал номера.

**Ученического раздела у базы пока нет:** витрина `/ege/topics/{n}`,
экраны PWA и генератор вариантов знают только профиль. Пока это банк для
учителя.

**Ошибку классификатора чиним переносом, а не переимпортом.** Номер задания
у задач банка ФИПИ проставлен правилами по тексту (`classify_ege_tasks.py`),
и серия может осесть не в своём номере: прикладные задачи с формулой и
задачи на совместную работу лежали в теме 06 «Уравнение». Переимпорт ради
такой правки слишком груб — он тащит за собой всё остальное. Есть команда:

```
php artisan tasks:move-groups --from=06 --to=09 --zadanie=5,6,7,8,12
```

Серия встаёт в **конец** темы-приёмника с новыми номерами: нумерация уже
лежащих там заданий не сдвигается, потому что отметки «решено» у учеников
позиционные. Блок берётся от последнего задания приёмника — иначе
`TaskBankRepository` разорвал бы блок «ФИПИ» надвое (блоки собираются по
смене номера у подряд идущих заданий).

## Связь с DB

JSON-банк — источник для **runtime**. В DB сохраняются:
- `tasks` (6163) — материализованные «пазловые» задачи (с навыками, мастерством)
- `task_skills`, `task_steps`, `step_blocks` — для пазл-механики
- В вариантах (`oge_variants`, `oge_variant_pool_tasks`) ссылка на JSON через `topic_id` + `zadaniya number` + `task id`

## Печатные варианты

Из банка ОГЭ собираются готовые к печати работы формата A4 — вёрстка
воспроизводит эталонный вариант ФИПИ. Команда `php artisan oge:print`,
подробности и границы — в [docs/print-variants.md](../../../../docs/print-variants.md).

Запускается **не на проде**: там нет pdflatex. Требует dev-VPS с TeXLive
и `rsvg-convert`.

Побочно закрыт пробел переноса банка: вводные условия блока заданий 1–5
(38 сюжетов) не попали в базу при импорте ФИПИ и приезжают отдельной командой
`tasks:import-intros` в таблицу `task_intros`; задания ссылаются на сюжет через
`tasks.intro_guid`. Без них задания 1–5 вне экранной вёрстки нечитаемы.
